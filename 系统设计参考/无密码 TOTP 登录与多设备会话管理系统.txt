📄 无密码 TOTP 登录与多设备会话管理系统
技术方案文档 v2.4

一、设计目标

1. 无密码认证：用户仅凭用户名 + TOTP 动态验证码完成登录。
2. 账号由管理员创建：预分配用户名，首次登录完成绑定。
3. 角色区分：仅两类角色——普通用户 与 管理员（前端角色），创建时指定。
4. 灵活会话管理：不限制设备并发数，通过活跃度与生命周期自动清理旧会话。
5. 差异化激活策略：
普通用户：绑定后需审批才能激活；
管理员：绑定验证通过后自动激活，无需等待审批。
6. 双轨审批机制：
主流程：服务器端人工审批（运维侧，无需系统登录）；
可选扩展：Web 审批界面（仅前端管理员角色可访问）。
⚠️ 本系统不设“超级管理员”，所有前端管理员权限对等。

二、核心流程
2.1 账号创建（服务器端人工操作）
运维人员通过服务器后台（如命令行工具、私有管理接口）创建用户；
必填信息：用户名、角色（user 或 admin）；
初始状态为 pending_activation，无 TOTP 密钥；
该过程不依赖 Web 系统登录，属于离线管理。

2.2 验证器绑定流程（用户首次登录）

1. 用户访问 Web 登录页，输入已分配的用户名。
2. 系统检测账号未绑定，进入绑定模式：
生成随机 TOTP 密钥；
展示标准 otpauth:// 二维码。
3. 用户使用微软 Authenticator 扫码并提交 6 位动态码。
4. 后端验证成功后，根据角色执行不同逻辑：
若为管理员：
自动将密钥设为生效状态（totp_secret = pending_secret）；
账号状态直接置为 active；
立即可登录，无需审批。
若为普通用户：
密钥暂存为 pending_secret；
状态设为 pending_approval；
提示：“绑定申请已提交，请等待审批”。
✅ 此设计加速管理员自助上线，同时保留对普通用户的强管控。

2.3 正常登录流程

1. 用户输入 用户名 + 当前 TOTP 动态码。
2. 后端校验：
账号状态为 active；
动态码有效（允许 ±1 时间窗口容差）。
3. 验证通过后：
创建新会话记录；
返回认证凭证。

2.4 验证器失效 / 丢失恢复流程

1. 用户点击“验证器失效”，输入用户名。
2. 系统生成新密钥并展示二维码。
3. 用户用新设备扫码并提交验证码。
4. 根据角色处理：
管理员：新密钥立即生效，旧密钥自动作废；
普通用户：进入 pending_reset 状态，需审批后生效。
🔒 安全保障：即使管理员可自助重置，其操作仍会被记录审计。

2.5 审批机制说明
（1）主审批通道：服务器端人工审批（当前默认）
由运维人员通过私有服务器接口或脚本完成；
无需登录 Web 系统，不依赖前端角色；
适用于所有待审批的普通用户请求。
（2）可选审批通道：Web 审批界面
若启用 Web 审批功能，则仅前端角色为 admin 的用户可访问；
普通用户不可见该入口；
审批操作仍受 TOTP 二次验证保护。

三、会话管理策略（无设备数量限制）
不限制并发设备数：用户可在任意多台设备登录。
会话清理策略：
自动续期：活跃会话在剩余有效期 <1 天时，自动延长至 7 天；
最大生命周期：单个会话最长存活 30 天（从创建起算）；
非活跃清理：后台任务定期清理满足以下任一条件的会话：
已过期（expires_at < now()）；
超过 30 天生命周期；
被手动撤销（如通过管理接口强制登出）。
✅ 该策略平衡了灵活性与资源控制，避免会话无限堆积。

四、用户角色与权限

角色 绑定是否需审批 是否可访问 Web 审批界面（若启用） 其他权限
------ ---------------- ------------------------------- --------
普通用户 是 否 仅管理自身会话
管理员 否（自动激活） 是 可审批他人绑定/重置申请（若 Web 审批启用）
⚠️ 角色仅影响 Web 系统行为，不影响服务器端人工审批流程。

五、数据库关键字段（users 表）

字段 说明
------ ------
username 唯一用户名
role 新增：user 或 admin
totp_secret 生效中的 TOTP 密钥（建议加密存储）
pending_secret 待处理的新密钥
status pending_activation / pending_approval / pending_reset / active / disabled
✅ role 在创建时写入，后续变更需通过管理接口。

六、安全与审计
所有绑定、重置、登录、审批操作均记录日志（含 IP、时间、操作类型）；
管理员自助激活行为同样被审计，确保可追溯；
会话 Token 不明文存储，仅保存哈希值；
敏感操作（如 Web 审批）需重新输入 TOTP。

七、总结

本方案实现：
灵活设备支持：不限制登录设备数，靠生命周期自动治理；
角色差异化体验：管理员绑定即用，普通用户走审批；
审批双模支持：当前以服务器人工审批为主，Web 审批为可选扩展；
安全闭环：无密码、无恢复码、TOTP 强认证、操作全审计。
典型场景：
运维创建前端管理员 → 管理员首次登录扫码 → 立即可用 → 可登录 Web 审批界面处理普通用户申请
运维创建普通用户 → 用户扫码提交 → 等待运维人工审批 → 审批后方可登录
